# 自解压压缩（`nekoc pack`）

把作品里体积很大的文本列表压缩，生成一个更小的 `.bcmkn`。作品启动时由积木脚本自动解压，**在官方 Kitten N 播放器里也能运行**，不需要插件。用于作品文件超过上传/请求大小限制的情况。

## 用法

```bash
nekoc pack 作品.bcmkn --out 作品.packed.bcmkn
```

```bash
nekoc unpack 作品.packed.bcmkn --out 作品.bcmkn
```

- `--min-kb`（默认 64）：只压缩 JSON 体积不小于这么多 KiB 的列表。
- `--window`（默认 8）：每项最多引用前面多少项。
- `--min-match`（默认 12）：最短引用长度。调大会减少片段数、解压更快，但文件更大。

Web Studio 顶栏的“压缩导出”按钮做同样的事（使用默认参数）。

## 原理

- 只处理全局列表、且每一项都是文本的大列表（数字列表、角色私有列表会跳过并说明原因）。
- 每一项编码成一串片段，片段之间用数据里没有出现过的字符分隔：
  - `~文本`：字面量（前缀防止官方 `text_split` 把 `007` 这类数字片段转成数字）；
  - `!d,s,l`：从前面第 d 项的第 s 个字符起复制 l 个字符（按 UTF-16 计，和官方 JS 截取一致，不会切开 emoji）。动画逐帧数据相邻项很像，大部分内容都能引用。
- 原列表初始值清空，编码后的数据放进隐藏列表 `__nekoc_pack_<原名>`。
- 解压脚本是真正的 Kitten N 积木：由 `src/pack/decoder.ts` 经 `ts/compile-ts.mjs` 编译一次，保存为 `src/pack/decoder-template.json`。打包时复制并改名 id，放在初始场景舞台的第一个脚本里，在“一次性执行”中逐项还原，完成后把 `__nekoc_pack_zready` 设为 1。
- 所有“当开始”类脚本最前面插入“如果未就绪就等待就绪”，所以作品自己的脚本看到的一定是解压后的数据；回到场景再次触发时条件已满足，不会额外等待。
- 打包时会用参考解码器自检，每个列表都必须逐项还原一致才会写入；`unpack` 能完全恢复原文件。
- 本项目自己的 VM 编译打包作品时直接在 Rust 里解包，不跑解码积木，所以 Web 播放器里没有加载等待。

## 实测（`projects/eisei/eisei_pen_128.bcmkn`）

| 参数 | 文件 | 片段数 |
|---|---:|---:|
| 原文件 | 57.5 MB | — |
| 默认（8 / 12） | 17.0 MB（29.5%） | 70.9 万 |
| `--min-match 24` | 21.8 MB（37.9%） | 39.1 万 |
| `--window 32 --min-match 32` | 23.9 MB（41.5%） | 29.5 万 |

解压耗时主要取决于片段数。在本项目 VM 上逐积木运行解码器（不走原生解包）需要 509 万条指令；本 VM 的文本拼接每次复制整串，比官方 JS 慢，因此只作上限参考。

## 尚未验证

- **没有在官方播放器里实测**。解码器用的积木（列表复制分割结果、截取文本、连接、按序号取项）都在本项目 VM 里验证过，但官方运行器里的耗时和细节（例如超长字符串性能）需要在官方编辑器里打开一次确认。
- 解压期间（几秒到十几秒，取决于数据和设备）作品的开始脚本在等待，舞台上会先显示初始画面。
