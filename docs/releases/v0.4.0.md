## 下载

**完整包**是解压就能用的版本，里面有：

- 本机后端 `web`（带 JIT）和命令行 `nekoc`
- PICKCAT 浏览器扩展（`extension/`）
- 示例作品：`works/` 下有《方界》《Pencraft》《星垒》和积木里的小语言模型，`samples/` 下有小示例
- TypeScript 前端和文档

不需要安装 Rust。只运行作品时也不需要 Node.js；用 TypeScript 编译作品需要 Node.js 18 或以上。

| 系统 | 文件 | 启动 |
| --- | --- | --- |
| Windows x64 | `nekoc-0.4.0-x86_64-pc-windows-msvc.zip` | 双击 `start.cmd` |
| Windows ARM64 | `nekoc-0.4.0-aarch64-pc-windows-msvc.zip` | 双击 `start.cmd` |
| macOS Apple Silicon | `nekoc-0.4.0-aarch64-apple-darwin.tar.gz` | 终端运行 `./start.sh` |
| macOS Intel | `nekoc-0.4.0-x86_64-apple-darwin.tar.gz` | 终端运行 `./start.sh` |
| Linux x64 | `nekoc-0.4.0-x86_64-unknown-linux-gnu.tar.gz` | `./start.sh` |
| Linux ARM64 | `nekoc-0.4.0-aarch64-unknown-linux-gnu.tar.gz` | `./start.sh` |

启动脚本会运行本机后端，并在浏览器里打开 <http://127.0.0.1:4173/play>。

- 把 `works/` 里的作品拖进播放器就能玩。
- 关掉命令行窗口，后端就停止。
- 浏览器需要支持 WebGL2，推荐 Chrome 或 Edge。

其他文件：

- **`nekoc-pickcat-extension-0.4.0.zip`：** 只有 PICKCAT 浏览器扩展（0.3.0）。解压后在扩展管理页选「加载已解压的扩展程序」。默认用 WASM 运行，不需要后端；在扩展弹窗里可以切到本机 Rust 后端（JIT，更快）。完整包里的 `extension/` 是同一份。
- **`nekoc-android-0.4.0.apk`：** Android 客户端，支持 arm64 和 x86_64，需要 Android 10 及以上。
- **`fttawa-nekoc-0.4.0.tgz`：** npm 包 `@fttawa/nekoc`，WASM 版编译器和播放器，在 Node.js 22+ 或浏览器里用，不需要 Rust。可以直接 `npm install @fttawa/nekoc`。
- **`SHA256SUMS.txt`：** 所有包的校验值。

**在线编译页：** 不装任何东西，打开 <https://nekox-lab.github.io/NekoC/>，在浏览器里写 TypeScript、检查、编译并运行，还能下载 `.bcmkn`。

## 主要更新

### 新的使用方式

- **六平台预编译包：** Windows、Linux、macOS 的 x64 和 ARM64 都在原生 runner 上构建，并在各自平台上做冒烟测试。以前只有 Windows x64。
- **WebAssembly 版：** 编译器、检查器和播放器都能编译成 WASM。
  - 有 npm 包 `@fttawa/nekoc`。用它编译出的作品和原生 CLI 逐字节一致，连积木 ID 都相同。
  - 播放器加了 WASM 后端，在 Worker 里跑虚拟机，不需要服务器。
- **在线编译页：** 部署在 GitHub Pages，类型检查、编译、运行全在浏览器里完成。
- **浏览器扩展 0.3.0：** 默认用 WASM 运行，装好就能用，不用另开后端。弹窗里可以在 WASM 和本机 Rust 后端之间切换。PICKCAT 上嵌入的 Kitten 4 官方播放器也会被接管。

### 写作品

- **`nekoc check`：** 检查以下几项：
  - TypeScript 类型
  - Kitten N 兼容性
  - 作品结构

  不输出文件；发现错误时退出码为 1，诊断信息带文件、行、列。加 `--json` 输出机器可读结果。`.bcmkn` 和 `.bcm` 文件也能检查。
- **`nekoc build`：** 内置空白作品，不再需要模板，默认输出到源文件旁边。
- **单文件舞台声明：** 一个 `.nk.ts` 文件可以同时写舞台和逻辑（见 `samples/stage_demo.nk.ts`）。
  - `sprite()` 支持多个造型、造型中心点和旋转角度。
  - 素材地址可以写成顶层 `const`。
- **普通 JS 写法：** 以下写法不用 NekoC 专用 API 也能编译：
  - 顶层语句
  - 普通对象（属性读写、`+=`、`++`）
  - `setTimeout` / `setInterval`
  - `Math.sign`、`cbrt`、`log2`、`hypot`、`atan2`
  - `Number.isInteger`、`Array.from({length}, fn)`、`Array(n).fill(v)`

  多个 `onStart` 仍然各自并发运行。
- **给 AI 编程助手：** 新增 `llms.txt` 和 `AGENTS.md`。

### 运行时

- **播放器后端 SDK（`nekoc::player`）：** 播放器协议抽成了库，WebSocket、HTTP、桌面壳和无头测试都能接入。文档见 `docs/player-sdk.md`。
- **Kitten 4：**
  - 云数据积木，以及本机文件云后端
  - 云变量监视器和排行榜
  - 过渡与滤镜，包括 ASCII、色相、扭曲和滑动
  - 软体网格
  - 场景激活顺序
  - 设备和传感器输入
  - 音频时间线
- **扩展接口 v2：** 新增报告器积木、布尔积木、事件帽子积木和积木元数据，支持版本协商，兼容 v1 扩展。调用扩展积木不再关闭整个作品的 JIT。
- **`nekoc run` 默认走新引擎：** Kitten N 和 Kitten 4 都用它。旧路径保留为 `--legacy-runtime`。

### 性能

- **JIT 分帧编译：** 每帧最多编译 2 个热点区域。重作品的最长帧从 40.4 ms 降到 5.4 ms，超过 10 ms 的帧从 7 帧降到 0。
- **Kitten N 不刷新屏幕循环：** 时钟改为按采样窗口检查，数值探针从 0.111 ms 降到 0.036 ms，修复了 0.3.0 引入的变慢问题。
- **JIT 循环尾快路径：** 数值循环从 0.0356 ms 降到 0.0258 ms。
- **「移到」专用路径：** 画笔循环从 0.0848 ms 降到 0.0597 ms。
- **其他优化：**
  - 广播分发、私有变量存储
  - 列表最后一项赋值
  - Kitten 4 列表监视器：一个小作品每帧从 7.9 µs 降到 5.0 µs
- **解释器栈帧：** 从 12760 B 降到 1672 B。

### 界面

- Studio、播放器、在线编译页、扩展弹窗和页面工具栏改成灰、白、黑配色。积木分类色和诊断的颜色不变。

### 仓库

- 大型作品移到 [NekoX-Lab/nekoc-works](https://github.com/NekoX-Lab/nekoc-works)，Android 客户端移到 [NekoX-Lab/nekoc-android](https://github.com/NekoX-Lab/nekoc-android)，两个仓库都保留了提交历史。

## 修复

- 舞台声明里的 `rotation` 被按角度写入，编辑器格式要求的是弧度。
- 数组字面量生成的积木缺少编辑器需要的 `items` 信息，在官方编辑器里打开会断开连接。
- 大列表作品启动时，检测麦克风会栈溢出（`Maximum call stack size exceeded`）。
- macOS 上解压后的包里 `nekoc check` 没有输出。原因是临时目录经过符号链接，入口判断失败。
- 本机后端缺少 `/backend.js` 路由，导致 Studio 和 `/play` 加载失败（只出现在 0.4.0 开发期间）。
- 格式错误的帧请求现在整帧拒绝，以前会先应用出错位置之前的那部分输入。

## 已知限制

- **安装包没有代码签名或公证。**
  - macOS 第一次运行需要在「系统设置 → 隐私与安全性」里允许，或者执行 `xattr -dr com.apple.quarantine <解压目录>`。
  - Windows 可能会弹出 SmartScreen 提示。
- **Linux 包：** 是 glibc 动态链接版本，在 Ubuntu 22.04 上构建，不适用于 Alpine 等 musl 系统。
- **APK：** 仍使用调试签名，以后换正式密钥时需要先卸载。
- **Kitten N 不刷新屏幕执行：** 让出边界还没有和官方每轮 30000 次迭代 / 4 ms 的规则完全对齐。
- **硬件、AI、网络、账户类积木：** 大多只有降级实现。
- **arm64 JIT：** 没有和解释器逐帧对比过。
