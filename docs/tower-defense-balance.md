# STARHOLD 六关战斗平衡验证

## 结论

**六关均能在设计规定的起始金币与正常战斗收益下获胜。** 同一套固定购买顺序、只在波间操作，在 25 / 50 / 100 ms 三种逻辑步长下全部取得三星。没有发现需要修改数值才能通关的关卡。

本报告是 **TypeScript 战斗核心的确定性 DSL 模拟**，不是官方 Kitten N 运行器实测；时间是游戏逻辑时间，不是测试程序耗时、浏览器 FPS 或原生积木执行预算。官方运行器验证由主任务单独记录。

- 日期：2026-11-02。
- 战斗代码：`modules/tower-defense/core.ts`，本次平衡任务没有修改该文件。
- 被测源码 SHA-256：`154dab20c1d3a4f800a9ee9d84a3f8f513a4f4650fb3a0737d933c1f67f130fa`。
- 自动验证：`tests/tower-defense-core.test.mjs`；全文件 **24 项通过**，其中新增六项各运行三种步长，另有一项比较三套替代策略的全部六关，共 **36 次完整战役模拟**。

## 方法与有效性

每关创建全新的状态，设定 `milestone=3` 和关卡编号后调用真实 `td reset`。随后策略只能读取冻结的状态副本，并通过白名单输入 `selectedPad / selectedTower / buildRequest / upgradeRequest / startWave / dt` 调用真实 `td tick`。

- 使用设计中的起始金币：180 / 190 / 210 / 230 / 250 / 280；核心生命20。
- 没有重写金币、生命、敌人、塔、冷却、波次、伤害、路程或基座坐标。
- 敌人正常生成、移动、攻击结算、漏怪、结算下一波；没有直接调用伤害或波次完成过程。
- 购买只发生在没有存活敌人的波间；逐项支付真实价格，不足时留钱等待下一波。没有出售，也没有战斗中的精确时机操作。
- 波间购买采用 `dt=0`，之后立即发起下一波。因此总时长只包含作战逻辑时间，不包含玩家阅读、思考、点选和等待时间。
- 每次金币变动记录所属原生过程：收入只允许来自 `td damage` 和 `td end wave`，支出只允许来自 `td build` 和 `td upgrade`，金币直接赋值只允许来自 `td reset`。
- 验证 `期末金币 = 起始金币 + 击杀收入 + 波次收入 − 塔投入`，投入同时与购买账单及全部 `tSpent` 求和核对。
- 验证每波应生成数量确实全部生成，每个生成敌人最终都被击杀或漏出；最终双Boss等组成没有被跳过。
- 六关实际生成总数：44 / 65 / 96 / 126 / 168 / 240；Boss总数：0 / 0 / 1 / 0 / 1 / 3。第六关第5波一只Boss，第10波两只Boss。

这些约束使通关结果可用于判断核心规则的可玩性与经济充足性。它们不等同于人工可用性测试，也不验证编译后原生循环调度与渲染效果。

## 替代开局与难度判断

其余布阵顺序保持与主策略相同，仅调整开局的4号与2号塔。以下均采用50 ms、波间购买、真实收益。单元格为“最终生命 / 星数”。

| 策略 | 关1 | 关2 | 关3 | 关4 | 关5 | 关6 |
|---|---|---|---|---|---|---|
| 主策略：先升满4号脉冲，再升满2号震爆 | 20 / 3 | 20 / 3 | 20 / 3 | 20 / 3 | 18 / 3 | 20 / 3 |
| `prismFirst`：先升满4号棱镜，再升满2号震爆 | 20 / 3 | 19 / 3 | 16 / 2 | 20 / 3 | 13 / 2 | 10 / 1 |
| `novaPulse`：先建2号震爆和4号脉冲，先升满震爆再升脉冲 | 20 / 3 | 20 / 3 | 17 / 2 | 20 / 3 | 17 / 2 | 13 / 2 |
| `mixedFirst`：先建4号棱镜和2号震爆，先升满棱镜再升震爆 | 20 / 3 | 19 / 3 | 15 / 2 | 14 / 2 | 9 / 1 | **第3波失败** |

`mixedFirst` 第六关在173.05逻辑秒时生命归零。昂贵的低级塔铺开以后，升级被推迟，早期漏怪减少击杀收入，随后形成经济劣势；不能据此判断该关不可通关。同关 `prismFirst` 仍可一星获胜，主策略可三星。

### 已观察到的平衡特征

1. **通关可行，且无需操作速度优势。** 三套清晰固定策略均能通过所有关卡，只是剩余生命明显不同；主策略完全不做战斗中购买。
2. **一级到三级的脉冲升级收益很强。** 满级脉冲170金币，单体名义DPS约54.76；满级棱镜350金币，约68.33，附带更远射程与护甲穿透。前几波混合敌人中，早期集中升级脉冲的经济效率很突出。其重甲有效DPS约35.60，因此中后期仍有棱镜价值。
3. **第五关开局比第六关更容易漏怪。** 主策略的“满级脉冲 + 一级震爆”需要270金币；第五关250金币无法同时拥有，第六关280金币可以。这造成该策略在第五关首波漏2只，而第六关零漏；不是关卡难度严格递增的证据。
4. **后期经济偏宽裕，当前主要考验开局。** 第六关最终波前仍有879金币，第9波后不再需要继续购买；第十波仍持续63.35秒，Boss提供了时长压力，但本次策略没有生命压力。
5. **前两关偏教学向。** 升级顺序合理时只用2座、3座塔即可满生命通过，适合作为引导；若期望更强的关卡差异，后续应结合真实玩家反馈评估。

本轮没有必要为“保证可通关”修改起始金币、塔伤害、敌人生命或奖励。建议先在说明或教学中突出“升级已有塔”和“选择能覆盖回折路段的基座”，并让官方运行器实测复现第六关购买表。若以后需要提高后期压力或平滑第五/第六关开局难度，应作为独立平衡迭代重跑这些经济约束测试，而不是在M1验证期间改数值。

## 复现

在仓库根目录离线执行：

```powershell
node --test tests/tower-defense-core.test.mjs
```

仅运行战役平衡，并输出各步长结果、50 ms逐项购买账单和逐波结果：

```powershell
$env:STARHOLD_BALANCE_REPORT='1'
node --test --test-name-pattern='campaign balance' tests/tower-defense-core.test.mjs
```

输出中的 `seconds` 是战斗核心累计的逻辑秒数。Node测试条目的毫秒耗时仅表示测试工具执行时间，不作为玩法时长或官方运行性能证据。
