# 星垒 / STARHOLD — Kitten N 原生塔防设计

## 目标与边界

- 交付：`projects/starhold/starhold.bcmkn`，通过 NekoC TypeScript 前端编译，资源以内嵌SVG造型保存。
- 运行目标：Kitten N 官方发布版运行器。只使用已有本地官方发行代码进行离线验证，阻断外部HTTP/WebSocket；不登录、不发布、不操作账号。
- 战场由背景造型、塔/敌人/弹体角色及原生特效组成。文字印章仅用于HUD、说明及云数据文本，不用画笔点阵或逐帧全屏绘图。
- 性能目标：优先30 FPS以上；记录实际游戏更新频率和浏览器rAF，不混淆二者。低画质关闭震动、减少弹体/粒子。无法完成的项目写入进度，不停止其他里程碑。

## 玩法

900×562舞台：上方HUD，左侧战场，右侧塔商店/升级，底部操作栏。敌人沿预设折线路径走向核心。12个固定基座可建塔，选择塔型后选择基座；选中已有塔后可升级或出售。空格发起下一波，P暂停，数字1–4选塔，U升级，X出售，B回菜单（原定Esc被官方事件过滤，M3实测后修改）。

资源：金币初始随关卡设定，击杀给钱，波次结束奖励。核心20生命，漏过普通怪扣1、精英扣2、Boss扣5。胜利清空最终波；生命归零失败。评价：胜利至少1星，生命≥12得2星，生命≥18且没有出售得3星。分数由击杀、剩余生命、关卡/波奖励构成；同一会话保存各关最好星数/分数。

## 模块与数据契约

- `modules/tower-defense/core.ts`：原生过程定义，战斗状态机、波次、敌人、塔、金币/胜负。主控制器以`callProc`调用。
- `tools/tower-defense/assets.py`：生成内嵌SVG背景、塔、敌人、弹体、按钮、覆盖面板；无下载。
- `tools/build-starhold.py`：拼接TypeScript、调用NekoC、注册角色/造型、注入固定数据、按里程碑裁剪、产出构建清单。
- `modules/tower-defense/ui.ts`：菜单、设置、操作说明、HUD印章、输入、显示池。
- `modules/tower-defense/cloud.ts`：M5本地排行和预设留言降级模块。原生公共云标量格式见云文档；当前产物没有已配置的云连接或云操作积木，线上接入未完成。
- `tools/tower-defense/offline-player.mjs` / `verify.mjs`：本地官方发行运行器验证，网络阻断记录、截图、游戏更新频率。

控制器全局：`mode`(0标题/1选关/2战斗/3胜利/4失败/5说明/6设置/7排行/8留言)、`level`、`wave`、`waves`、`gold`、`lives`、`score`、`stars`、`paused`、`quality`、`shake`、`frames`、`ready`、`selectedTower`、`selectedPad`、`startWave`、`buildRequest`、`upgradeRequest`、`sellRequest`、`dt`、`waveActive`、`bossAlert`。

池：敌人24槽，列表`eAlive/eType/eHP/eMax/eX/eY/eProgress/eSlow/eFlash`；塔12槽，`tType/tLevel/tCooldown/tShot/tTargetX/tTargetY/tSpent`；基座`padX/padY`；记录`bestScore/bestStars`6项。所有列表索引1起；空区间不能使用原生数字遍历。未使用槽隐藏，避免创建/销毁抖动。采用原生角色池，不强求使用克隆。

原生过程名：`td reset`重置所选关；`td tick`以`dt`推进一轮；`td build`消费`buildRequest`基座和`selectedTower`；`td upgrade`/`td sell`消费选中基座；`td next wave`启动波次。UI负责把请求交给控制器，所有战斗数组只由控制器写入。

逻辑时间使用官方计时器差值并限制单步最大.1秒，暂停期间不推进战斗；渲染角色每次调度读取最新池。计时器50ms量化的影响列入性能记录。

## 美术与特效

暗色太空基地、青色能量路线、琥珀色建造基座。不同塔有独立轮廓，敌人以形状+颜色双重区分。尽量使用小型SVG造型，避免大透明纹理叠加。

M4：每塔一个可复用弹体/拖尾，命中缩放反馈、爆炸光环、升级脉冲、6槽伤害数字、Boss横幅。原定受击闪白滤镜因原生渲染性能和默认值问题移除。高画质启用有限震动；低画质保留攻击反馈。HUD不高于5Hz更新。FPS持续低于目标则主动关闭昂贵项并记录取舍。

## 云数据与安全（本地官方源码审计后修订）

排行榜：六关各自前10；仅保存匿名显示标识、关卡、分数及星级，避免存储个人信息。只在胜利结算时尝试提交，有冷却且有失败提示。并发更新/权威校验限制必须说明，客户端分数不能冒充防作弊榜。

留言：采用**预设短语白名单**（如“加油”“这关好难”“试试冰塔”），避免未成年人自由文本风险；单条最多16个UTF-16单位，30秒冷却、基础禁词/链接/联系方式拦截，仅显示最近12条。读入云端数据也重新检查长度与词语；异常条目忽略。无私信、无外链、无真实姓名。

源码确认：10个公共云变量创建上限、字符串写入128个UTF-16单位、100ms客户端合并写入；后者不是服务端频率承诺。未找到公共云列表支持，原生榜单上限4，不能直接为6关各建1榜。预留9个公共云标量：6关各1个最高分摘要，另3个留言分片，每片4条。122单位/分片，详见专用文档。无事务/CAS，客户端合并无法保证并发写入不丢失，也不保证防作弊。

服务端资源ID必须由合法创建流程分配。当前不登录、不联网，不能完成资源开通或在线同步验收。交付中本地排行和安全留言可运行，原生云绑定只有设计，尚未实现；不伪造资源ID。

原生配额和同步语义以`docs/tower-defense-cloud.md`记录为准。无网络/无发布环境只能验证积木结构和离线降级，不能伪称线上同步通过；不为测试而发布或登录。

1. 单关核心：基本塔、敌人、路径、购买、生命/金币、胜负；官方离线发布运行器实测与FPS。

5. 原生云功能：源码限制说明、排行榜/安全留言、离线降级；加载运行与FPS，明确在线未验证项。
