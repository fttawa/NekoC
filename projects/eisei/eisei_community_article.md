# 用原生积木和画笔，在 Kitten N 里播放一支 ASCII 音乐 PV

最近做了一个有点折腾、但也很有意思的项目：把《衛星》的 ASCII 音乐 PV 移植到了 **Kitten N**。

画面里的每个字符，都由原生画笔文字打印绘制。完整音乐、初始化、播放、停止和重播，也都在项目内部完成。

目前做到了 **128×36 字符网格、1280×720 舞台、143.5 秒完整播放**。下面聊聊它是怎么实现的，以及过程中踩过的几个坑。

## 从终端字符动画，到原生画笔

这个移植基于开源项目 **eisei-ascii-pv**。原工程提供了终端版动画数据，里面记录着每一帧的字符、位置和颜色。

我用自己正在开发的 **NekoC** 工具链，把 TypeScript 播放逻辑编译成 Kitten N 原生积木，再将字符数据和音频打包进 `.bcmkn` 项目。

整个流程大致是：

```text
原工程 ANSI 字符动画
        ↓
解码字符、位置与颜色
        ↓
生成紧凑的按帧数据
        ↓
NekoC 编译原生积木播放器
        ↓
打包为 Kitten N 项目
        ↓
原生画笔打印 + 音乐播放
```

成品运行时使用的是 Kitten N 自身的积木、列表、计时器、音频和画笔能力。

## 最大的问题：字符太多，怎么画得动？

128×36 的网格，一帧就有 **4608 个字符格**。

如果逐格设置位置、颜色，再一个一个打印，积木执行开销会很大。因此，这个版本采用了几种优化。

### 1. 把同一行、同一种颜色的字符合并打印

原生文字打印不能直接指定终端等宽字体，所以字符的宽度并不完全一致。

为了尽量保持网格对齐，我先测量字宽，再用不同宽度的 Unicode 空格补齐位置，把同一行中颜色相同的字符合并为字符串打印。

这样既减少了打印次数，也能保留日文宽字符的位置关系。不过，不同设备的字体仍可能影响最终显示效果。

### 2. 只重画发生变化的行

每行内容都有对应的 ID。播放下一帧时，先比较新旧行：

- 内容相同，就保留；
- 内容变化，先用背景色擦除整行，再打印新内容。

这种方式能减少重复绘制。播放器即使跳过了某些帧，也能直接恢复目标帧的画面。

### 3. 数据按帧存储，用到时再展开

早期版本把大量字符指令存成独立列表元素，完整项目运行起来明显变慢。

排查后发现，编辑器对大列表的观察和复制也会带来开销。于是改为将数据存成**按帧组织的字符串**，播放时只拆分当前帧需要的数据。

这个调整对完整项目的运行表现帮助很大。

## 音乐和画面怎么同步？

播放器使用计时器计算当前应该显示哪一帧。

如果某个复杂画面绘制耗时过长，就跳过已经过期的素材帧，继续追赶当前播放时间，避免画面越播越落后。

项目还加入了初始化和静音前导：

1. 点击开始，建立运行所需的缓存并进行音频预热；
2. 初始化完成后，按 **Enter**；
3. 经过 **3 秒静音前导**，进入正片。

播放中按 **Q** 可以停止，按 **Enter** 可以从头播放，片尾也支持重播。

## 两个印象很深的坑

### 文件能预览，却不能导入

最初的高分辨率完整版约 **54.9 MiB**，编辑器预览能够运行，但本地导入时提示“新作品创建失败”。

后来检查网络请求，发现上传接口返回了 **HTTP 413：请求体过大**。

于是重新整理存储格式，换用更紧凑的分隔符，并删除重复保存的固定字号数据，将文件缩小到约 **43.1 MiB**。这一轮优化保留了原有的 1435 帧素材和完整音频，紧凑版随后成功导入运行。

### 动画在播放，旧字符却留在画面上

这个问题更隐蔽：音乐和帧数都正常，画面却越叠越乱。

最终定位到 NekoC 编译器对“变量取负”表达式的处理：生成的减法积木漏接了输入，导致擦除横线的左端坐标无效。画笔没有正确回到行首，自然擦不干净旧字符。

修复后，我补了一项真正检查画面的验证：在一行的两端和中间放入旧像素，再让项目执行原生擦除，检查是否还有残留。

修复版连续 **72 次行擦除检查，残留像素均为 0**。

这也提醒了我：**能运行、能播完，不等于画面一定画对了。**

## 当前版本的效果

| 项目 | 当前规格 |
|---|---|
| 字符网格 | 128×36 |
| 舞台尺寸 | 1280×720 |
| 正片时长 | 143.5 秒 |
| 素材采样 | 10 FPS，共 1435 帧 |
| 绘制方式 | 原生画笔文字打印 |
| 音频 | 内嵌完整音轨 |
| 文件大小 | 约 43.1 MiB |
| 操作 | Enter 播放／重播，Q 停止 |

修复版在本次官方编辑器测试中，完整播放实际完成了 **1409 帧，平均约 9.82 FPS**，初始化、片尾、重播和停止检查均通过。

这里的 **10 FPS 是素材采样帧率**，实际绘制速度会随设备和场景变化。另外，1280×720 指舞台尺寸，画面细节仍由 128×36 的字符网格决定。

建议放大舞台观看，小预览窗口里字符会比较小。
