# PENCRAFT · Kitten N 原生画笔生存

导入文件：[`pencraft.bcmkn`](pencraft.bcmkn)。在 Kitten N 中导入后点击开始，按 **H** 收起操作说明。

当前文件 **767,338 字节（约 749 KiB）**。

本轮防闪烁修复也提供独立文件名：[`pencraft_flicker_fixed.bcmkn`](pencraft_flicker_fixed.bcmkn)，内容与主文件相同。

这是有限体素世界的第一人称生存实验。地形由原生画笔线段填充投影面，不使用点阵屏、逐像素帧缓冲或浏览器注入绘图。项目包含原生积木和初始数据，可在官方编辑器执行。

## 操作

| 按键 | 功能 |
|---|---|
| WASD | 移动 |
| 方向键 | 转向、俯仰 |
| 空格 | 跳跃 |
| 按住 F | 挖掘准星指向的方块 |
| G | 放置选中的方块 |
| 1–7 | 草、土、石、木、树叶、铁矿、灯笼 |
| C | 合成下一等级镐 |
| T | 用木头合成灯笼 |
| L | 切换手持照明（背包需有灯笼） |
| E | 吃苹果；挖树叶获得苹果 |
| B | 近距离攻击敌人 |
| H / P / R | 帮助 / 暂停 / 重生 |
| V | 调整填面扫描带宽度，2–10；越大越省笔画 |
| N | 调整视距，7–15 |

初始背包有 12 块土、3 个苹果。先采木头，再制作镐、挖石头和铁矿。铁矿需要石镐。饥饿耗尽后失血，饱食时缓慢回血；夜晚生成追逐玩家的敌人。死亡后按 R 恢复生命、饱食度与出生位置。

### 配方

- 木镐：3 木，40 次耐久。
- 石镐：3 石 + 1 木，100 次耐久。
- 铁镐：3 铁矿 + 1 木，220 次耐久。
- 灯笼：1 木 → 4 灯笼。

## 实现与优化

- 世界大小 **16 × 12 × 16**，种子 **1337**，初始 **1455** 个实体方块。
- 构建时贪心合并为 **190** 个外露矩形面。
- 背面、视锥和距离剔除；可见面二分插入排序；近裁剪面处理后透视投影。
- 每面只变换一次原点，其他角点由两个相机空间边向量推导；三角函数乘积每帧预计算。
- **防闪烁呈现**：几何、光照和 HUD 先生成原生笔画命令列表，计算期间保持上一张完整画面。准备好后才清屏，以无循环的有界自制积木调用树集中提交，避免在绘制中途遇到原生循环让出。
- 凸多边形双边链扫描，边段变化时计算斜率，扫描带内增量更新交点；细轮廓补缝。
- 临时标量及工作列表使用原生脚本变量。持久初始数据在开始时复制一次，避开每笔更新舞台观察列表的开销。
- 挖掘和放置只修改六个接触界面，将受影响的合并面切成至多四块；无需重建整个区块。
- 固定方向明暗、初始接触暗部、昼夜、距离降饱和、手持光和已放置灯笼的局部亮度。
- 物理使用有界小步；生存时间基于计时器差。静止且地面未改变时跳过重复碰撞查询。
- 敌人使用画笔绘制的朝向摄像机形体，并以世界射线检查视线遮挡。

## 性能与限制

性能必须以官方运行器实测为准。早期版本约 **0.37 FPS**；临时列表与边链填面版曾测得 **4.11 FPS**（开启 CPU 采样）；工作网格列表优化版测得 **6.24 FPS**（未开启 CPU 采样）。这些是不同阶段的记录，不能当作同条件的精确倍数比较。

加入完整生存、灯光和细轮廓后，近期单次基准在 **2.12–5.24 FPS** 间波动；6.24 FPS 不是当前交付版成绩。最终验证改为连续三个8秒窗口，保留各窗口和总平均，测试过程中关闭 CPU 采样器。

防闪烁修复前的交付版实测为平均2.41 FPS，记录保留在 [`pencraft-verification-release/report.json`](pencraft-verification-release/report.json)。环境为官方 Kitten N 编辑器、headless Edge、640×360 舞台、默认视距9与扫描带10、静止初始视角；这是原生完成帧计数，不是 GPU 刷新率，也不是移动或采矿全过程的平均速度。

**尚未达到稳定 30/60 FPS。** 默认视距 9、扫描带上限 10，优先减少绘制成本。分辨率为 640×360；笔画填面会有边缘近似和阶梯感。防闪烁修复针对清屏与半帧暴露，低帧率造成的运动不连贯仍然存在。集中提交期间主线程需完成一批笔画，有输入延迟的代价。

其他边界：

- 世界有限；没有无限区块生成或游戏存档。
- 面中心深度排序不是 Z-buffer，特殊交叠角度可能有遮挡错误。
- 局部照明是简化距离衰减，不是光线追踪；灯光不计算墙体投影阴影。
- 敌人是简化追逐/爬台阶逻辑；可见性射线检查中心位置，非逐像素遮挡。
- 短时超长停顿会限制物理追赶量，避免穿墙；不保证所有设备上的实时速度一致。
- 单帧最多8192条绘制命令；超限时保留上一张完整画面，不清屏提交残缺帧。此时可调粗扫描带或降低视距。提交前在旧帧仍完整时让出一次，给有界调用树留足原生单步调用预算。

## 构建与验证

```powershell
python tools/build-pencraft.py
node --test tests/voxel.test.mjs tests/unary-negative.test.mjs
node node_modules/typescript/bin/tsc --noEmit --strict --lib es2020 ts/nekoc.d.ts samples/pencraft.ts modules/voxel/present.ts
$env:NEKOC_NODE_MODULES='D:\AppData\Local\Temp\opencode\nekoc-kitenn\node_modules'
node tools/verify-pencraft.mjs samples/pencraft-verification-flicker-fixed
```

设置 `NEKOC_PROFILE=1` 可额外保存 CPU profile；正常基准默认关闭采样器。验证器只在截图请求时捕获下一次清屏前的完整画笔帧。玩法测试会设置固定位置、时间等测试条件，再执行项目原生逻辑；这不等同于所有条件均通过纯手工按键完成。

验证覆盖移动、转向、挖掘、放置、采木、合成木镐、进食、合成与放置灯笼、夜间生成敌人、仰望天空、死亡和重生。报告与完整帧截图保存在验证输出目录。通用 `editor-compat.mjs` 对这个大型工程的二次工作区载入曾长时间停滞；本项目验证器改为检查官方导入后当前可见工作区的积木字段及连接，并单独报告检查范围。

**28项 JS 工具测试通过**，严格 TypeScript 检查通过。新增命令队列回归逐笔比对直接绘制与延迟提交的线段、笔宽和文字，并检查命令超限时不清屏。

验证器现在会在每次浏览器 `requestAnimationFrame` 检查“已经清屏但完整帧计数尚未更新”的窗口，不能再只依赖完整帧截图。旧版对照在3493次刷新检查中发现3303次半帧；第一轮修复版在3175次刷新检查中为0次。观察代码不替换绘图、不修改运行器调度参数。`NEKOC_PRESENT_ONLY=1` 可只跑静止、转向、移动呈现检查；`NEKOC_PROJECT` 可指定对照项目，`NEKOC_ALLOW_PARTIAL=1` 仅用于记录已知闪烁的旧版。

最终修复版完整玩法回归：**5869次浏览器刷新检查，0次半帧，271次完整提交**；零页面错误、零检测到的运行告警。当前可见工作区571个积木的字段及连接检查通过；还覆盖扫描带2、视距15与帮助叠层。三段8秒基准为 **6.74 / 7.74 / 6.11 FPS，总平均6.87 FPS**，单次集中提交中位耗时14.4ms。该次测量不代表所有设备保证达到同样速度。报告：[`pencraft-verification-flicker-fixed/report.json`](pencraft-verification-flicker-fixed/report.json)。

源代码：`samples/pencraft.ts`、`modules/voxel/`。构建器 `tools/build-pencraft.py` 负责模块拼接、将绘图调用接入 `present.ts` 的原生命令队列、生成有界提交树、原生脚本变量转换、初始网格与项目打包。仍然使用原生画笔线段，没有像素帧缓冲或浏览器注入绘图。
